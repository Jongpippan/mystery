## Responsibility and relay boundaries

1. Codex prepares one complete self-contained full-script source packet, including accepted PR-B01 and all remaining scene/challenge/branch/hint assignments.
2. ChatGPT writes bounded complete scene units **within the same writing assignment/conversation**, maintains actual draft files and a progress manifest, then assembles a full draft ZIP. A complete chapter is not required in one response. If response limits interrupt work, the courier's only text is `계속`; the writer resumes from its manifest, not a fresh creative brief.
3. The user returns the assembled full draft ZIP once. A partial checkpoint ZIP is honestly marked incomplete and is not full delivery. If the writer cannot preserve files across its environment, it must provide a real checkpoint and explain the minimum restore action; no claim of automatic background work or guaranteed one-response completion.
4. Codex reads and validates all actual sources, makes small local consistency edits, and consolidates any necessary substantial rewriting into one targeted revision assignment. Do not force a revision for every scene or require a predetermined number of external rounds. Remaining material issues may still require further revision; do not promise a fixed quality-independent relay count.
5. Codex accepts the assembled script only after full scene/alternative-order/knowledge/logic review, then adapts/implements/verifies the whole game. No intermediate user creative approval or playtest is introduced.

The intended normal file-relay pattern is one full draft return, followed by a consolidated revision return only if needed. Internal drafting units do not each become a Codex/user handoff. This reduces file transport and repeated prompting; it cannot guarantee that no `계속` input will be needed in ChatGPT.

## Script ownership and within-draft continuity

PR-B01's[accepted source](scripts/pr-b01.ko.md) is fixed input. Everything newly written inside the full assignment remains a candidate. The writer may use earlier candidate scenes as **working continuity**, explicitly distinguished from Codex acceptance; it must propagate any proposed change to affected candidate sections and record it. It cannot silently change supplied case truth, accepted text, essential evidence, judgment, access or child innocence.

The writer keeps complete chapter files plus per-file English notes. At response limits, append whole complete scenes, save actual files if supported, and list the next unfinished C/branch/H IDs. Never replace unwritten responses/hints/revisits with summaries or mark the whole draft complete from the ideal route alone. Progress state tracks the source packet/version and files actually written, not an unsupported assertion of future work.
