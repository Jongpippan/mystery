# Caused events, access and persistence requirements

Version: `plan-v1`. Narrative transition contract only; runtime schema/implementation deferred until G0/G1. This specifies behavior required by the designed story, not an existing game engine.

## Time and eligibility

Reading, tool inspection, drafting, hints, cancellation and notes never advance fictional time. Scheduled activities advance on explicit participation/scene completion, not a real countdown. The prologue's witnessed public interval is a scene with suspendable tools, not a free-travel segment. In free investigation the player may visit accessible strands in either order; eligible essential appointments persist until completed. World cause and discovery are separate records.

Story chronology: prologue Oct21; CH01–CH03 Oct22 morning/afternoon; CH04–CH05 Oct22 later; CH06 Oct23 after overnight conservation. A date transition is offered only after the current required reasoning and immediate scenes resolve. It does not silently create missing evidence. No timed puzzle or paid resource gates required proof.

## Event records

All once-only events save pending/running/completed, current scene and line, acquisition queue/acknowledgements and exit place. Their stable V ID is the idempotency key for world effects, independent of display name. A save during a line resumes that line without rerunning the effect. Multiple pending events run in stated order only when the player is in an eligible safe place; they never overwrite an active conversation.

## Narrative state that must have one source

When adaptation starts, use one shared state authority and one public action API for chapter/date/place/access, acquired E and object transformation history, proven K, met P and last-observed locations, current/original S versions, D/Q status, relationship B, event/acquisition queues, conversations/logged chosen branch, points/submission IDs/recovery state, hints, answer drafts and saves. UI may keep temporary focus/hover locally, but must not duplicate writable case progress in a second store/hook/context.

Save must preserve answer type/step, selected statement/person/evidence/reason, item ordering, timeline arrangement, note text, tool-return stack, search/filter/sort, scroll/focus anchors, active scene line and pending detail acknowledgments. Inspection changes presentation only. An actual travel action checks connection/access and is separate from map viewing. No tool click may submit a claim.

Atomic behavior to implement and test later: input validates preconditions → one submission/event identity → determine result → apply one cost or one success/unlock → save all related state → show response/acquisition. An interrupted UI must not apply twice on resume. Narrative data must derive from the accepted script indexed in `scripts/README.md`; adaptation follows the G0/G1 decision recorded on2026-09-14.
