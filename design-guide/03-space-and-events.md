# 03. 물리 지도, 재방문, 움직이는 사건

## 지도는 사건이 가능한 공간을 보여준다

공간·시간이 추리에 영향을 주는 작품은 실제 연결 관계에 따른 평면도를 만든다. 방 이름 카드의 임의 나열을 동선 증거로 사용하지 않는다. 층, 출입구, 복도, 계단, 창문, 잠금 장치, 우회로, 시야 차단, 소리 전달, 운반물 크기와 통과 제약을 필요한 범위에서 정의한다.

지도 좌표와 경로 데이터는 같은 공간 모델을 따른다. 실제 통로가 없는데 가까이 그려져 건너갈 수 있다고 오해하게 하거나, 그림에는 문이 있는데 이동 데이터에는 연결이 없는 상태를 피한다. 축척 지도인지 개념도인지 표시한다. 개념도라면 그림의 길이를 이동 시간으로 추측하게 하지 않고 구간별 소요 시간을 제공한다.

| 통로에 기록할 값 | 의미 |
|---|---|
| 출발·도착 장소, 층, 방향 | 양방향/일방통행 여부 포함 |
| 길이 또는 이동 시간 범위 | 걷기·짐 운반·계단 등 조건 포함 |
| 이용 조건 | 열쇠, 출입 권한, 사건 상태, 잠금 시간 |
| 관측 조건 | 어디에서 누구를 볼 수 있고 소리는 어디까지 들리는지 |
| 물체 제약 | 통로 폭·높이, 물건 크기·운반 인원 |
| 정보 출처 | 도면·현장 측정·실험·증언 등 플레이어가 아는 근거 |

동선 검증은 `이동 시간 + 문 개폐·작업 시간 + 대기·목격 구간`으로 한다. 최단 경로만 계산하고 잠긴 문이나 작업 시간을 무시하지 않는다. 범인이 이용한 경로뿐 아니라 경쟁 가설의 우회 경로도 검토한다.

지도에는 현재 위치, 알려진 연결, 접근 제한 이유, 이미 확인한 인물의 위치와 **마지막 확인 시점**을 표시한다. 실시간 추적 근거가 없는데 인물 위치를 계속 갱신하지 않는다. 추리 중에는 과거 상태·경로를 열람할 수 있고, 현장 이동과 지도 열람을 별도 행동으로 구분한다.

## 장소의 생애를 설계한다

각 주요 장소에 `첫 방문 → 사건 변화 → 재방문 → 이후 재해석`을 작성한다. 권장 기본은 주요 장소 최소 3곳에서 의미 있는 재방문이 발생하는 것이다. 재방문마다 다음 중 하나 이상이 실제로 달라져야 한다.

- 다른 인물의 목적 있는 이동으로 대질·갈등·목격이 생긴다.
- 수리·운반·청소·자료 회신 등으로 이전에 없던 물건이나 기록이 생긴다.
- 빛·소리·기계 상태가 달라져 기존 물체를 새롭게 검사한다.
- 이전 증거와 새 지식을 결합해 원래 있던 흔적을 이해한다.
- 플레이어의 앞선 선택 때문에 누군가 도움을 주거나 설명 방식을 바꾼다.

“2장이므로 서랍에 정답 문서가 생성됨”은 충분한 인과관계가 아니다. 누가 언제 왜 놓았는지, 앞서 조사했을 때 왜 없었거나 이해할 수 없었는지 기록한다. 처음 조사한 물체가 비어 있었다면 나중의 내용물 변화에 원인과 흔적이 필요하다.

## 사용자 모르게 변해도 발견은 공정하게

모든 변화를 즉시 “새 증거!” 알림으로 알려 줄 필요는 없다. 대신 필수 변화에는 다음 경로 중 하나 이상을 확보한다.

1. 다음 업무·약속·통상 이동 때문에 그 장소를 다시 가게 되는 자연스러운 동선.
2. 변경된 빛·소리·부재·인물 대사처럼 관찰 가능한 징후.
3. 막힘 상태에서 조수가 제안하는 단계별 재방문 힌트.

필수 이벤트는 놓쳐도 대기하거나 재발견 경로를 갖는다. 안내 없이 전 장소를 매번 전수 클릭해야 하는 구조, 한 번 지나가면 영구히 실패하는 숨은 시간 창은 기본 조사 구조로 사용하지 않는다. 선택 이벤트는 놓칠 수 있지만 핵심 진상의 유일한 근거를 담지 않는다.

## 이벤트를 데이터로 명시한다

각 `V`에 다음 항목을 작성한다.

```text
ID / 발생 원인 / 선행 E·K·선택 / 발생 가능 장소·사건 시각
발동 조건 / 방해 조건 / 우선순위 / 한 번만 실행할 효과
실제 세계 변화 / 플레이어가 그 변화를 알게 되는 계기
발견 대사 / 새 E·K·S / 인물·경로 변화 / 메인 이미지 A
종료 조건 / 원래 장면으로 돌아갈 지점 / 놓쳤을 때 대체 경로
대기·실행·완료 저장 값 / 다시 불러올 때 재개 위치
```

세계 변화와 플레이어의 발견을 분리한다. 이미 일어난 운반을 뒤늦게 목격했다고 표현하지 않고, 이동 흔적·인수 기록·증언으로 확인하게 한다. 복수 이벤트가 동시에 준비되면 우선순위와 큐를 적용하여 대사가 겹치거나 중요한 장면이 덮이지 않게 한다.

### 가상 예시: 배수로 재방문

| 단계 | 세계 상태와 플레이어 행동 |
|---|---|
| 첫 방문 | 물이 차 있어 바닥 확인 불가. 작업자의 배수 예정 안내를 들음 |
| 원인 | 플레이어가 설비 자료를 확인하면 작업자가 안전 조건을 확인하고 배수 시작 |
| 숨은 변화 | 다른 방 조사 중 배수 완료. 별도 증거 획득 팝업은 없음 |
| 발견 경로 | 돌아오는 복도에서 모터 소리가 멎음. 미방문이 이어지면 조수가 작업 완료 확인을 제안 |
| 재방문 | 바닥 운반 자국 발견, 기존 동선 가설의 물체 방향을 재검증 |
| 증거 공정성 | 배수 전 접근 불가와 흔적 보존 원리를 앞서 설명. 새 흔적을 배수로 우연히 조작하지 않음 |

이 예시를 그대로 신작 줄거리로 채택할 의무는 없다.

## 빈도와 장면 연출

권장 기본은 장마다 주요 이벤트 2~3개와 조사 반응·관계 대화다. 주요 이벤트는 증거·관계·접근성·목표에 변화를 주어야 한다. 단순 “자료를 찾았습니다” 알림을 사건 수로 세지 않는다.

이벤트 시작 시 메인 화면은 해당 상황 컷으로 전환하고, 인물 표정·소리·대사가 같은 상태를 설명한다. 중요한 시각 변화는 최소 한 번 사용자의 확인을 거쳐 진행하여 짧은 타이머로 사라지지 않게 한다. 텍스트를 읽는 속도에 따라 사건이 망가지지 않도록 기본 시간은 행동·챕터에 따른 사건 시간으로 처리한다. 시간 제한을 별도 장치로 쓸 경우 읽기·열람 중 처리와 실패 회복을 먼저 설계한다.

이벤트 중 저장 후 복구하면 같은 장면과 대사 위치에서 이어지고, 증거·보상·인물 이동은 중복 발생하지 않는다. 종료 후에는 현재 세계 상태에 맞는 장소 이미지로 복귀한다.
