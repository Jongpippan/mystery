# 06. 자료 이미지와 상황 연출

## 시각 정보도 사건의 사실이다

인물·배경·물건·문서·이벤트 이미지의 공통 미술 방향을 먼저 정한다. 중요한 물건의 크기, 개수, 형태, 훼손, 위치, 인물 복장과 소지품을 자산 원장에 기록한다. 추리에 쓰이는 관찰 특징이 장면마다 달라지면 논리 오류로 취급한다.

배경에 실제로 없는 출입문을 장식으로 그리거나, 아직 열리지 않은 상자의 내용물을 미리 보여주지 않는다. 텍스트로 “관찰 도해”라고 적었다는 이유만으로 자료 간 핵심 형태 불일치를 허용하지 않는다.

## 모든 자료의 고유 썸네일

각 증거 `E`에는 고유 `thumbnailAsset`과 확대용 `detailAsset` 또는 정확한 문서 렌더링을 연결한다. 썸네일은 상세의 핵심 시각 특징을 축약한다. 예를 들어 영수증은 길고 접힌 종이와 도장, 출입 카드는 구멍과 띠, 녹음기는 버튼 배치, 사진은 고유 촬영 구도로 구분한다.

서로 같은 문서 유형이면 문서의 접힘·배치·대표 도해·실제 확인된 표식으로 구분한다. 번호나 색상만 바꾼 복제본으로 채우지 않는다. 똑같이 보여야 하는 두 문서가 사건의 일부라면 중립적인 촬영 배경·배치로 구별하고, 실제 위조 판별 단서를 썸네일 단계에서 과장하지 않는다.

자료명, 유형, 관찰 가능한 한 줄 설명을 이미지와 함께 제공한다. 파일명·대체 텍스트·툴팁에 `범인증거`, `가짜`, 아직 모르는 인물 이름처럼 미래 결론을 넣지 않는다.

## 메인 장면 전환

| 플레이 상태 | 메인 이미지의 역할 |
|---|---|
| 첫 방문 | 공간 구조, 주목할 물체, 분위기를 보여주는 전경 |
| 일반 대화 | 현재 장소와 발화 인물·대상 관계를 보여주는 구도 |
| 주요 이벤트 | 바로 일어난 변화가 보이는 전용 상황 컷 |
| 핵심 증거 발견 | 발견 위치와 물체 상태를 연결하는 근접 장면 |
| 재방문 | 달라진 조명·물체·인물 배치를 실제 상태와 일치시킴 |
| 추리 재구성 | 확인된 사실과 가설의 시각화를 구별하여 표시 |
| 이벤트 종료 | 사건 이후 상태에 맞는 장소 화면으로 복귀 |

장소 배경 위에 인물 초상을 올리는 방식만으로 모든 주요 이벤트를 처리하지 않는다. 주요 이벤트에는 그 변화를 읽을 수 있는 장면 구도 또는 의미 있는 상태 변형을 준비한다. 재구성 이미지에는 “가설”, “확인된 사실”, “회상”을 구분해 이미지 자체가 정답을 인증하는 것처럼 보이지 않게 한다.

## 자산 제작과 기록

자산 `A`마다 용도, 등장 조건, 연관 E/V/L/P, 원본·파생 경로, 제작 방법, 반드시 보여줄 것, 아직 보여주면 안 되는 것, 대체 텍스트, 검수 결과를 기록한다.

사진·삽화·초상은 작품에 맞는 이미지 제작 도구를 사용한다. 정확한 문서 수치·평면도·시간표·UI는 코드·벡터·텍스트 렌더링 등 정확도를 보장하는 방식을 선택할 수 있다. 생성 이미지에 중요한 한국어 문장·숫자를 전부 맡기지 말고 원문 데이터로 읽을 수 있게 제공한다. 도구 선택은 현재 제작 환경의 지침을 따른다.

장면은 대사창과 탭이 놓일 영역을 고려해 구성하고, 작은 화면에서 잘라 보아도 필수 관찰 정보가 사라지지 않게 한다. 관찰이 필요한 상세 이미지는 확대해서 볼 수 있게 한다.

## 검수 방식

1. 전체 자료 썸네일을 실제 목록 크기로 모아 한 화면에서 비교한다. 상세에 들어가지 않고 원하는 자료를 찾을 수 있는지 확인한다.
2. 인물 표정·복장, 핵심 물체의 형태·수치, 지도 출입구를 장면 사이에서 대조한다.
3. 이벤트 발생 전·도중·이후를 캡처하고 해당 V의 상태와 맞는지 확인한다.
4. 새 게임 초반에 미래 단서가 이미지·대체 텍스트·자료 미리보기로 드러나지 않는지 확인한다.
5. 저장 복구, 빠른 넘김, 작은 화면, 글자 확대에서도 깨진 이미지·무관한 장면·단서 가림이 없는지 확인한다.

파일 존재 검사만으로 미술 검수를 통과시키지 않는다. 실제로 렌더링된 이미지를 보아야 한다. 현재 문서 작성 단계에서는 이미지 제작 자체를 요구하지 않으며, 이 기준은 신작의 자산 제작 단계에 적용한다.
